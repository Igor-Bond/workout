# Трекер тренировок

Персональный журнал тренировок: план, свободный порядок выполнения, запись
каждого подхода, прогресс и статистика. Работает офлайн, ставится на главный
экран как приложение.

Полное описание — [docs/SPEC.md](docs/SPEC.md).
Что уже сделано — [docs/STATUS.md](docs/STATUS.md).

## Состояние

Идёт переработка на версию 2.0. Готов этап 1 из 9: каркас, навигация,
разделение файлов, сервис-воркер. Разделы, отмеченные в интерфейсе пунктирной
рамкой с номером этапа, ещё не реализованы.

Версия 1 сохранена в [legacy/](legacy/) как точка возврата.

## Запуск

Приложение — набор статических файлов, сборка не нужна. Но модули ES и
сервис-воркер не работают через `file://`, поэтому нужен любой локальный
сервер:

```bash
npx serve .
```

Затем открыть выданный адрес. Для проверки установки на телефоне подойдёт
`http://<адрес компьютера>:3000` в одной сети — либо опубликованная версия.

## Разработка

```text
index.html          разметка приложения, без стилей и скриптов
css/style.css       все стили, цвета переменными в :root
sw.js               кэш и офлайн; при правке файлов поднимать APP_VERSION
manifest.json       описание PWA

js/main.js          точка входа
js/app.js           экраны и маршрутизация (#/history/<id>)
js/config.js        настройки
js/version.js       версия приложения
js/core/            инфраструктура: события, диалоги, формат, экран
js/services/        база, синхронизация (этапы 2 и 8)
js/modules/         экраны

docs/               ТЗ, состояние, правила Firestore
tests/              проверки логики, запускаются в браузере
```

Правила, которые важно не нарушить:

- работа с базой — только через `js/services/db.js`, нигде больше;
- любое значение от пользователя проходит через `ui.esc()` перед вставкой
  в разметку;
- обработчики вешаются через `data-action`, а не `onclick`;
- цвета берутся из CSS-переменных, а не задаются в JavaScript;
- при изменении состава файлов обновлять список в `sw.js`.

## Публикация

GitHub Pages из ветки `main`. Файл `.nojekyll` обязателен — иначе Pages
игнорирует каталоги, начинающиеся с подчёркивания, и часть путей ломается.
Все пути в проекте относительные, поэтому приложение работает и из
подкаталога.
