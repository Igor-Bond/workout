# Трекер тренировок

**Приложение:** https://igor-bond.github.io/workout/

Персональный журнал тренировок: план, свободный порядок выполнения, запись
каждого подхода, прогресс и статистика. Работает офлайн, ставится на главный
экран как приложение.

Полное описание — [docs/SPEC.md](docs/SPEC.md).
Что уже сделано — [docs/STATUS.md](docs/STATUS.md).
Чем оно было прежде и почему поменяли — [docs/DECISIONS.md](docs/DECISIONS.md).
Разбор и что стоит починить — [docs/AUDIT.md](docs/AUDIT.md).
Набор тестировщиков и анкета — [docs/BETA.md](docs/BETA.md).

## Состояние

Все девять этапов пройдены: каркас, база на IndexedDB со справочником
упражнений и переносом истории, движок тренировки со свободным порядком,
выполнение с рекордами и таймером отдыха, шаблоны, история с фильтрами,
календарь и прогноз следующей тренировки по ритму.

Приложение полностью рабочее и на телефоне, и на компьютере: тренировка,
история, календарь, статистика с графиками, личные рекорды, вес тела,
резервная копия.

Синхронизация с Google подключена и проверена: завершённые тренировки
переносятся между устройствами. Без входа приложение работает так же
полно, просто локально.

Сверх исходного плана добавлены интервальные тренировки (§50): табата с
отсчётом от часов, сигналами, выложенными в звуковой движок заранее, и
голосом, называющим следующее упражнение. Для тех, кто открыл приложение
впервые, есть справка «Как пользоваться» (§51) — отдельный экран из
профиля.

Стабильные версии помечены: `git tag -n5`. Откатываться — к последней,
порядок в [docs/DEPLOY.md](docs/DEPLOY.md) §2.2.

## Запуск

Приложение — набор статических файлов, сборка не нужна. Но модули ES и
сервис-воркер не работают через `file://`, поэтому нужен любой локальный
сервер:

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1
```

Затем открыть `http://localhost:4173`. Порт меняется ключом `-Port`.
Node в проекте не используется, но если он установлен, подойдёт и
`npx serve .`.

## Проверки

Открыть `/tests/index.html` на том же локальном сервере. Проверки идут в
браузере, без сборки и без установки чего-либо; зелёная полоса сверху и
галочка в заголовке вкладки означают, что всё прошло.

Работают они на отдельной базе `WorkoutTrackerTestDB` — настоящая история при
запуске не затрагивается. Сервис-воркер страница снимает сама, иначе она
показывала бы не то, что лежит в репозитории, а то, что осталось в кэше у
этого браузера.

На каждый push и pull request те же проверки прогоняет GitHub Actions:
поднимает статический сервер, открывает эту же страницу настоящим браузером
и читает итог. Само приложение при этом остаётся без сборки и без
пакетов — браузер ставится только на бегунке.

## Разработка

```text
index.html          разметка приложения, без стилей и скриптов
css/style.css       все стили, цвета переменными в :root
sw.js               кэш и офлайн; при правке файлов поднимать APP_VERSION
manifest.json       описание PWA

js/main.js          точка входа
js/app.js           экраны и маршрутизация (#/history/<id>)
js/config.js        настройки
js/version.js       версия приложения
js/core/            инфраструктура: события, диалоги, формат, экран
js/services/        db.js — единственная точка работы с базой
                    migrations.js — базовый справочник и перенос версии 1
                    auth.js, sync.js — вход и обмен с Firestore
                    backup.js — выгрузка и загрузка файла
js/modules/         экраны
vendor/             локальные копии зависимостей (Dexie, Firebase SDK)
js/firebase.config.js  конфигурация проекта Firebase — заполнить перед входом

docs/               ТЗ, состояние, разбор, развёртывание, бета, правила Firestore
tests/              проверки логики, запускаются в браузере
tools/serve.ps1     локальный сервер для разработки
tools/make-icons.ps1 генерация иконок, включая maskable
tools/check-precache.ps1  сверка списка офлайн-файлов с деревом проекта
tools/export-v1.html  выгрузка истории версии 1 из другого браузера
```

Правила, которые важно не нарушить:

- работа с базой — только через `js/services/db.js`, нигде больше;
- любое значение от пользователя проходит через `ui.esc()` перед вставкой
  в разметку;
- обработчики вешаются через `data-action`, а не `onclick`;
- цвета берутся из CSS-переменных, а не задаются в JavaScript;
- при изменении состава файлов обновлять список в `sw.js`.

## Публикация и синхронизация

Приложение опубликовано: https://igor-bond.github.io/workout/

Порядок целиком — в [docs/DEPLOY.md](docs/DEPLOY.md): проект Firebase,
правила доступа, GitHub Pages, перенос истории из прошлой версии.

GitHub Pages из ветки `main`. Файл `.nojekyll` обязателен — иначе Pages
игнорирует каталоги, начинающиеся с подчёркивания, и часть путей ломается.
Все пути в проекте относительные, поэтому приложение работает и из
подкаталога.
